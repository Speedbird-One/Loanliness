# Loan repayment prediction for applicants without credit history

UE24CS352A Machine Learning mini-project.
Team: **Tanmay T A (PES1UG24CS492)** and **Vedanth Kiran (PES1UG24CS523)**

Based on *Loanliness: Predicting Loan Repayment Ability by Using Machine Learning Methods*
(Liang, Jin, Wang, Stanford) and the Kaggle [Home Credit Default Risk](https://www.kaggle.com/competitions/home-credit-default-risk/data) data
(307,511 loan applicants, 8.1% defaulted).

## Quick start for reviewers (no dataset, no training)

The trained models (`models/`) and a small set of demo files (`demo_data/`) are committed on purpose, so the demo runs straight after cloning.

```
git clone https://github.com/Speedbird-One/Loanliness
cd Loanliness
pip install -r requirements.txt
python -m streamlit run app.py
```

Or use the command-line version:

```
python cli.py assess
python cli.py replay --kind defaulter --seed 3
```

* On macOS/Linux use `python3` and `pip3` if `python`/`pip` are not found.
* `requirements.txt` pins the library versions the models were saved with. Models are pickled, so a very different scikit-learn or LightGBM version may warn or fail to load.
* `demo_data/heldout_sample.parquet` holds 3,000 applicants from the held-out test split (never used for training or tuning) so the "replay" feature works without the full dataset.
* Result tables for every experiment are collected in [`RESULTS.md`](RESULTS.md); figures and raw tables are in `reports/`.

## What this project does

The paper asks whether borrowers *without* a credit history (students, first-time borrowers) can still be
assessed fairly. We test that directly and fix several weaknesses in the paper's evaluation:

| Paper | This project |
|---|---|
| Drops every row with a missing value (307K → 102K rows) | Keeps all rows; LightGBM handles missing values natively, other models impute inside a pipeline |
| Reports accuracy on a *balanced* test set | Test set keeps the natural 8% default rate; reports ROC-AUC, PR-AUC and recall in the riskiest 20% |
| Concatenates one-to-many tables | Aggregates each auxiliary table per client (mean/max/min/sum/count); `bureau_balance` is aggregated twice |
| Never evaluates the "no credit history" case | Three feature sets: **C** thin-file, **A** application only, **B** application + all tables |
| Decision at the default 0.5 cut-off | Cost-based threshold `1/(1+R)`; models are well calibrated (mean predicted 8.0% vs actual 8.1%) |
| No look at protected attributes | A with-gender and a without-gender variant, plus a gender audit |

### Feature sets

* **A**: `application_train` only (128 features incl. engineered affordability ratios).
* **B**: A + aggregated `bureau`, `bureau_balance`, `previous_application`, `POS_CASH_balance`, `installments_payments`, `credit_card_balance`.
* **C**: A without `EXT_SOURCE_*` and `AMT_REQ_CREDIT_BUREAU_*` (119 features): what a lender could see for a thin-file applicant.

### Model variants

* **With gender** (default): uses `CODE_GENDER`; for statistics.
* **Without gender** (`--compliant` flag): drops the columns listed in `PROTECTED` in `src/features.py`.

Dropping the column removes the *explicit* input only. `python -m src.audit` measures how much that costs in accuracy,
how outcomes differ by gender, and whether gender can still be inferred from the remaining features (it can).

## Headline results

Tuned LightGBM, held-out test set (61,503 applicants). Full tables: [`RESULTS.md`](RESULTS.md).

| Feature set | ROC-AUC (with gender) | ROC-AUC (without gender) | PR-AUC | Defaulters caught in riskiest 20% |
|---|---|---|---|---|
| C: thin-file | 0.720 | 0.714 | 0.197 | 46.0% |
| A: application only | 0.771 | 0.768 | 0.261 | 53.8% |
| B: all tables | 0.792 | 0.790 | 0.293 | 57.9% |

(PR-AUC and recall shown for the with-gender models; the baseline for PR-AUC is 0.081.)

## Reproducing everything from scratch

Only needed to re-run the experiments; reviewers can skip this section.

### Setup

Python 3.10 or newer.

```
pip install -r requirements.txt
```

### Data

The dataset is not in the repository (about 2.5 GB unzipped). You need a free Kaggle account.

**Step 1: accept the competition rules (once).** Open the [competition page](https://www.kaggle.com/c/home-credit-default-risk), click *Join Competition* (or *Late Submission*) and accept the rules. Without this, downloads fail with a 403 error.

**Step 2: give the Kaggle CLI your credentials.** On Kaggle go to profile picture → *Settings* → *API* and create a token. Use whichever form Kaggle gives you:

| | Windows (PowerShell) | macOS / Linux (bash) |
|---|---|---|
| **`kaggle.json` file** | Save it to `C:\Users\<you>\.kaggle\kaggle.json` | `mkdir -p ~/.kaggle && mv ~/Downloads/kaggle.json ~/.kaggle/ && chmod 600 ~/.kaggle/kaggle.json` |
| **Token string** (this session only) | `$env:KAGGLE_API_TOKEN="<token>"` | `export KAGGLE_API_TOKEN=<token>` |
| **Token string** (permanent) | `[Environment]::SetEnvironmentVariable("KAGGLE_API_TOKEN","<token>","User")`, then open a new terminal | add the `export` line to `~/.bashrc` or `~/.zshrc`, then open a new terminal |

Check that it works with `kaggle competitions list` (it should print a table). Never commit credentials.

**Step 3: download and unzip into `data/raw/`.**

*Windows (PowerShell):*

```powershell
mkdir data\raw -Force
$files = "application_train","bureau","bureau_balance","previous_application","POS_CASH_balance","installments_payments","credit_card_balance","HomeCredit_columns_description"
foreach ($f in $files) { kaggle competitions download -c home-credit-default-risk -f "$f.csv" -p data/raw }
Get-ChildItem data\raw\*.zip | ForEach-Object { Expand-Archive -Path $_.FullName -DestinationPath data\raw -Force }
Remove-Item data\raw\*.zip
```

*macOS / Linux (bash):*

```bash
mkdir -p data/raw
for f in application_train bureau bureau_balance previous_application \
         POS_CASH_balance installments_payments credit_card_balance \
         HomeCredit_columns_description; do
  kaggle competitions download -c home-credit-default-risk -f "$f.csv" -p data/raw
done
for z in data/raw/*.zip; do
  [ -e "$z" ] || continue
  unzip -o "$z" -d data/raw && rm "$z"
done
```

If `unzip` is missing on Linux, install it (`sudo apt install unzip`) or replace the `unzip` line with `python3 -m zipfile -e "$z" data/raw`.

**Step 4: check the result.** `data/raw/` should contain these 8 files (the three largest tables are several hundred MB each):

```
application_train.csv   bureau.csv   bureau_balance.csv   previous_application.csv
POS_CASH_balance.csv   installments_payments.csv   credit_card_balance.csv   HomeCredit_columns_description.csv
```

Windows: `Get-ChildItem data\raw`. macOS/Linux: `ls -lh data/raw`.

*Browser alternative:* on the competition's *Data* tab click *Download All*, then unzip into `data/raw/`
(Windows: `Expand-Archive home-credit-default-risk.zip -DestinationPath data\raw -Force`;
macOS/Linux: `unzip -o home-credit-default-risk.zip -d data/raw`).
`application_test.csv` and `sample_submission.csv` are not used and can be deleted.

### Running the pipeline

Run everything from the repository root (commands are the same on every platform). All randomness uses seed 42; the 80/20 train/test split is stratified and made
**before** any imputer, encoder, scaler or sampler is fit. Add `--sample 50000` to `baseline`, `compare` or `tune` for a quick dry run.

| Step | Command | Time (approx.) |
|---|---|---|
| 1. Feature sets A and C | `python -m src.features` | seconds |
| 2. Feature set B | `python -m src.aggregate` | a few minutes; needs several GB of RAM |
| 3. Untuned baselines | `python -m src.baseline --sets A C B` | ~1 min |
| 4. Model comparison | `python -m src.compare zoo --set A` (and `B`, `C`) | 1-4 min each |
| 5. Imbalance study | `python -m src.compare imbalance --set A` (and `B`, `C`) | 1-5 min each (SMOTE on B is slowest) |
| 6. Tune + save models | `python -m src.tune --set B --trials 30 --timeout 30`<br>`python -m src.tune --set A --trials 10`<br>`python -m src.tune --set C --trials 10` | ~30 min for B, a few min for A and C |
| 7. Same, without gender | repeat step 6 with `--compliant` | same |
| 8. SHAP + threshold | `python -m src.explain --set B` (and `A`, `C`; add `--compliant` for the other variant) | ~1 min each |
| 9. Gender audit | `python -m src.audit --set B` (and `A`, `C`) | ~1 min each |
| 10. Summary tables | `python -m src.summarize` | seconds |
| 11. Demo files | `python -m src.export_demo` | seconds |

Outputs: `data/processed/*.parquet` (cached features, not committed), `models/lgbm_<set>[_compliant].joblib`, `reports/` (CSV, JSON and PNG files), `RESULTS.md`, and `demo_data/`.
Files for the without-gender variant carry a `_compliant` suffix.
After retraining, re-run step 11 and commit the updated `models/` and `demo_data/`.

## Demo details

Both demos use only `models/` and `demo_data/`.

**Streamlit app**

```
python -m streamlit run app.py
```

* *Assess a new applicant*: a form for someone with no credit history; shows P(default), an approve/reject decision, and the top drivers (TreeSHAP).
* *Replay a held-out applicant*: draws a real applicant the models never saw and compares the thin-file model with the full model.
* The sidebar switches between the with-gender and without-gender variants and sets the cost ratio *R* (reject if P(default) ≥ 1/(1+R)).

**Command line**

```
python cli.py assess                                   # example applicant
python cli.py assess --income 90000 --credit 400000 --annuity 22000 --goods 360000 --age 29 --years-employed 2
python cli.py assess -i                                # prompts for every field
python cli.py assess --variant compliant --cost-ratio 10
python cli.py assess --list-options                    # valid values for the choice fields
python cli.py replay --kind defaulter --seed 3         # held-out applicant, both models
```

## Limitations

* One stratified split; differences smaller than about 0.004 AUC are within noise. Tuning effort differed by set (30 trials for B, 10 for A and C).
* The data contains only applicants who were approved, so outcomes for rejected applicants are unobserved.
* The cost ratio *R* is an assumption, not a measured quantity; results are reported across *R* = 2 to 20.
* The imbalance study uses logistic regression only.
* The without-gender variant removes an input; it is not a guarantee of equal outcomes or of legal compliance, which depends on jurisdiction.
